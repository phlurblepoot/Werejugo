# Phase 1.1 — Safety Net & Project Hygiene Implementation Plan

**Roadmap:** `docs/superpowers/specs/2026-09-26-completion-roadmap.md` → Milestone 1 → 1.1
**Goal:** Make the current app safe to put on the public internet and give the project a CI safety net, without starting the larger rework (accounts/admin arrive in 1.3, the access layer in 1.4).

**Branching:** all Milestone 1 work lands on `claude/cool-hopper-pku4ne`, reviewed as one milestone PR to `main` (see roadmap §8, 2026-09-26 **Changed**).

**Conventions**
- Backend commands run from `backend/`, frontend from `frontend/`. Backend tests need PostGIS (see `CLAUDE.md`).
- Tests first where behaviour is testable: write the failing test, watch it fail, implement, watch it pass.
- Never weaken an assertion to get green. If a test exposes a real problem, fix the problem.
- Tick the roadmap item in the same commit as the work.

**Files:** create `.github/workflows/ci.yml`; modify `.github/workflows/publish-images.yml`; fix `frontend/src/api/share-backup-client.test.ts`.

1. `ci.yml`, triggered on `pull_request` and on `push` to `main`:
   - `roadmap` job: checkout with full history → `node scripts/roadmap.mjs --check`; on PRs also `--changed-since origin/${{ github.base_ref }}`.

2. `publish-images.yml`: publish on `main` (`latest` + `sha-…`), on `v*` tags (semver tags), and on `claude/**` branches as **preview** tags named after the branch (never `latest`), so a milestone can be tested on Unraid before it is merged.
3. Fix the jsdom `Blob` realm failure: assert on blob behaviour (`size`, `text()`), not `instanceof`.

**Verify:** YAML parses; frontend suite fully green locally.

### Task 2 — Persist storage (B2)

**Files:** `docker-compose.yml`, `unraid/werejugo-backend.xml` (+ the other two templates' branch URLs), `.env.example`, `README.md`, `backend/src/lib/storage-check.ts` (new), `backend/src/index.ts`.

1. Compose: a named `storage` volume mounted at `/app/storage`.
2. Unraid backend template: a required `Storage` path → `/app/storage` (`/mnt/user/appdata/werejugo/storage`); fix template URLs that point at the old branch so they point at `main`.
3. `.env.example` documents `STORAGE_DIR`/`UPLOADS_DIR` (for non-Docker runs) and the new secrets (Task 3).
4. Boot-time guard: in a container (`/.dockerenv` present) with `NODE_ENV=production`, log a loud warning when `STORAGE_DIR` or `UPLOADS_DIR` is not on a mounted volume (read `/proc/self/mountinfo`). Pure function `isOnMount(path, mountinfo)` unit-tested.
5. README: correct local-dev steps (the backend reads real environment variables; there is no `.env` loader).

### Task 3 — Required secrets (B4)

**Files:** `backend/src/config.ts`, `backend/src/lib/filesign.ts`, `docker-compose.yml`, `.env.example`, tests.

1. `validateSecrets(env)`: in production, throw with a clear message (including `openssl rand -hex 32`) when `JWT_SECRET` is missing, equals a known placeholder, or is shorter than 32 characters. Outside production, allow it but warn.
2. `FILE_SIGNING_SECRET` (optional): used for signed file URLs. If unset, derive one from `JWT_SECRET` with HMAC so the raw JWT secret never signs files directly.
3. Compose: `JWT_SECRET: ${JWT_SECRET:?…}` (compose refuses to start without it) instead of a default.

**Tests:** unit tests for `validateSecrets` (missing / placeholder / short / good; non-production passes).

### Task 4 — Close public signup and lock down backup/restore (B3, stopgap until 1.3)

**Files:** `backend/src/routes/auth.ts`, `backend/src/lib/instance.ts` (new), `backend/src/routes/backup.ts`, `backend/src/config.ts`, `frontend/src/pages/LoginPage.tsx`, `frontend/src/pages/SettingsPage.tsx`, `frontend/src/api/client.ts`, tests.

1. `GET /api/auth/config` → `{ firstRun, signupOpen }`. `firstRun` = no families exist. `signupOpen` = `firstRun || ALLOW_SIGNUP=true`.
2. `POST /api/auth/register` with `mode: "create"` → 403 when signup is closed. `mode: "join"` (invite code) keeps working.
3. "Instance owner" = the owner of the oldest family. `GET /api/backup` and `POST /api/restore` → 403 for everyone else. `/api/auth/me` returns `isInstanceOwner`.
4. Restore safety: validate everything first (manifest, `db.json`, a `storage/` directory, table names ⊆ known tables); stage files next to the storage dir; only then run the DB transaction, then replace the **contents** of the storage dir (it is a volume mount point in Docker, so it can't be removed or renamed). Also include `UPLOADS_DIR` in backups as `uploads/` and restore it the same way (icons and map overlays were being lost).
5. Frontend: the login page asks `/api/auth/config`; "New family" is shown only when signup is open, and a first-run server opens straight into "Set up Werejugo". Settings shows backup/restore only to the instance owner, and a restore signs the user out afterwards (their account may no longer exist).

**Tests:** register-create blocked after the first family; join still works; `ALLOW_SIGNUP=true` reopens it; backup/restore 403 for a member and for the owner of a second family; restore of an archive without `storage/` is rejected **and leaves data untouched**; round-trip includes uploads.

A non-blocking card (bottom-right on desktop, bottom on phones) with a dismiss button (remembered per family in `localStorage`, wrapped in try/catch), refetched on navigation so it disappears once data exists. Its links navigate normally.

### Task 6 — GPX/KML import (B5)

**Files:** `backend/src/routes/import.ts` (+ new test), `frontend/src/components/MapSetEditor.tsx`.

`ST_Force2D` on every geometry; a MultiLineString becomes one LineString with all parts in order; unsupported geometries are counted as skipped; features past the 2000 cap are reported as `truncated`. The frontend message shows skipped/truncated counts.

**Tests:** GPX with `<ele>` imports; a two-segment track imports as one drive containing both segments' points; a Polygon is skipped.

### Task 7 — Dates (B6)

**Files:** `backend/src/db/pool.ts`; `frontend/src/lib/dates.ts` (new, + test); display call sites (`Sidebar`, `ItemDetail`, `MapView` popup, `TripBoard`, `TripDetail`, `TripsPanel`, `BlackoutManager`, `StatsPanel`, `DocumentList`).

1. `pg.types.setTypeParser(1082, v => v)`: `DATE` columns come back as `YYYY-MM-DD`, independent of server timezone. This also fixes date inputs that were blank when editing (they received timestamps).
2. `formatDate("2024-06-01")` → `Jun 1, 2024` (parsed as a local date, never through UTC); `formatDateRange(start, end)` collapses shared month/year.

**Tests:** backend — a trip's `startDate` is `2024-06-01` with `TZ=Europe/Berlin`; frontend — formatter cases including timezone safety.

### Task 8 — Hardening

**Files:** `backend/src/index.ts`, `backend/src/routes/auth.ts`, `backend/src/lib/upload.ts`, `frontend/default.conf.template`, tests.

1. `@fastify/rate-limit` on login (10/min) and register (5/min), keyed by `CF-Connecting-IP` when present (Cloudflare Tunnel), else the request IP; `trustProxy` on.
2. Login does a dummy bcrypt compare for unknown emails (no timing-based account discovery).
3. `@fastify/helmet` security headers on API responses (CSP handled by nginx for the HTML app).
4. SVG no longer accepted for uploads or URL downloads; `/uploads/*` responses get `X-Content-Type-Options: nosniff` and a `default-src 'none'` CSP so any existing SVG can't run script.
5. `/api/auth/me` returns 401 when the token's user no longer exists.
6. nginx: security headers + a CSP for the app; `/api/restore` and `/api/backup` get unlimited body size / long timeouts / no buffering.

**Tests:** 11th login in a minute → 429; SVG upload → 400; `/me` for a deleted user → 401; helmet header present. The CSP is verified by loading the production build in Chromium with the header applied and checking for violations.
