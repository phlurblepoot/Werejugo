# Phase 1.6 — One Map Implementation Plan

**Roadmap:** `docs/superpowers/specs/2026-09-26-completion-roadmap.md` → Milestone 1 → 1.6 (design in §3.5)
**Goal:** One map of everywhere the family has been — including places on trips shared with other families — filtered by trip, person, year, kind and family, with the filters in the URL. Map sets and the legacy side panels go away; search results open the thing they point at on every page.

**Decisions this plan relies on:** roadmap §2 ("one map + filters", "remove legacy map panels") and §7.3 (custom image overlays are dropped with map sets unless the owner uses them).

---

### Backend

- Migration `0003_one_map.sql`: a family's custom base-map style (the first map set's `style_url`, if any) moves into `families.settings.map.styleUrl`; `map_set_visits` and `map_sets` are dropped. New families no longer get an "Our Map" set.
- `GET /api/visits`: every place the family may see (its own and shared-trip places), in **three queries** instead of one per place (places, waypoints, photos + people), each with `familyId`/`familyName`, `canEdit` and `personIds` (for the person filter).
- Import: `POST /api/import` (GPX/KML/GeoJSON; optional `tripId` puts the imported places on a trip), replacing `POST /api/map-sets/:id/import`.
- Map-set routes, the `map_set` access kind, map sets in backups/exports/seed are removed. Restoring an older backup ignores its `map_sets`/`map_set_visits` tables.

### Frontend

- Map page: loads `GET /api/visits`; the sidebar's map-set picker becomes **filters** — search, kind, trip, person, year and (when anything is shared) family — all stored in the URL (`/map?trip=…&person=…&year=…&kind=flight,cruise&family=mine|shared|<id>`), so any view can be bookmarked or linked.
- Shared-trip places carry a "by <family>" chip in the list and detail; only editable ones offer edit/delete/drag.
- The map fits to the visible places (no saved per-set view); the base-map style comes from family settings; the style no longer loads twice on mount.
- The legacy Trips, Photos (gallery), Stats and Export panels leave the sidebar: Trips and Photos link to their pages; **Travel stats** stays reachable from the Map's header menu until the Stats page (4.2); pin styles & icons, map appearance and GPX/KML import live in the header menu too.
- Deep links on every page: `/map?visit=` selects the place, flies to it and opens it; `/planning?trip=` (done in 1.5), `/people?person=`, `/documents?doc=` open the item. The command palette's results already use these URLs.

### Tests

Backend: the visits list (own + shared places, attribution, `canEdit`, `personIds`, no N+1 regressions in behaviour), import with and without a trip, migration of the map style, restore of a backup that still has map sets, isolation suite updated. Frontend: URL filters (reading and writing), deep links on each page, shared chips and edit gating on the map list/detail, header menu entries.

---

## Outcome (2026-09-26)

Built as planned, with these differences:

- **Visits list:** four queries, not three: places, waypoints, photos and people (the people query feeds `personIds`).
- **Family filter:** `family=mine|others`, not `mine|shared|<id>`. With one or two partner families, "who added it" is the useful question, and the trip filter already narrows to one shared trip.
- **Map fitting:** the map fits every place once, when they first load, unless a place is selected. It doesn't refit on each filter change, because the view would jump while typing. Fitting to the filtered pins stays with 3.1.
- **Photo deep links:** `/photos?photo=` was added too. Search already produced it and nothing opened it.
- **Migration 0003:** keeps the style of the family's *oldest map set that has one*, not simply the oldest set, so a style on a second set isn't lost. `src/db/migrations.test.ts` checks it by running the migration on old-shape data inside a rolled-back transaction.
- **Found in QA:** a "stay" place blanked the map because the web app didn't know the kind. There is now one `ITEM_KINDS` list with Stay. The legend counts what the other filters leave and tolerates unknown kinds. The panel is renamed "Travel stats".
- **Removed in the wrap-up:** the generic `POST /api/uploads`. It only served custom map overlays and let any signed-in user put images into the public `/uploads`. The SVG-refusal test now runs against `POST /api/icons`.
- **Left for later:** the 14 older `.modal-backdrop` dialogs don't close on Esc (added to 3.6). Custom image overlays went with map sets, per §7.3. Map-set share links had already been removed before this phase.
