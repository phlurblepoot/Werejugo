# Phase 1.2 — Design System & Responsive Shell Implementation Plan

**Roadmap:** `docs/superpowers/specs/2026-09-26-completion-roadmap.md` → Milestone 1 → 1.2
**Goal:** A real design system (tokens, light/dark/system themes, icons, core components) and a shell that works as well on a phone as on a desktop. Module *content* is redesigned in the later phases that touch each module; this phase makes every screen theme-aware, gives every page the same header, and fixes the worst phone layout breakage.

**Design direction.** Calm, photo-forward, "travel journal" rather than "admin dashboard": warm paper-white surfaces in light mode, deep ink in dark mode, one ocean-teal accent, soft 10–14px radii, generous spacing, Lucide line icons instead of emoji in the chrome. System font stack (fast, native on every device).

**Conventions:** as Phase 1.1 (tests first where behaviour is testable; tick roadmap items in the same commit).

---

### Task 1 — Tokens, themes, colour sweep

**Files:** `frontend/src/styles/tokens.css` (new), `frontend/src/styles/global.css`, `frontend/src/lib/theme.tsx` (+ test), `frontend/public/theme-init.js`, `frontend/index.html`, `frontend/src/main.tsx`.

1. Tokens as CSS custom properties: colour roles (`bg`, `surface`, `surface-2/3`, `border`, `border-strong`, `text`, `text-muted`, `text-subtle`, `accent`, `accent-hover`, `accent-contrast`, `accent-soft`, `danger/warning/success` + soft variants, `focus`), radii, spacing scale, type scale, shadows, layout sizes (header, rail, tab bar).
2. Themes: light values on `:root`; dark under `@media (prefers-color-scheme: dark)` guarded by `:root:not([data-theme="light"])`, and again under `:root[data-theme="dark"]`.
3. Legacy variables (`--bg`, `--panel`, `--panel-2`, `--border`, `--text`, `--muted`, `--accent`, `--accent-hover`, `--danger`, `--radius`) become aliases of the tokens, so existing screens follow the theme immediately.
4. Sweep hard-coded UI colours in `global.css` (and chrome colours inline in components) onto tokens. Data colours (trip colours, pin palettes) stay as they are.
5. `ThemeProvider` / `useTheme()`: preference `system | light | dark`, stored in `localStorage` (try/catch), applied as `data-theme` on `<html>`. `public/theme-init.js` applies the stored preference before first paint (an external file, because the CSP forbids inline scripts). `index.html`: `viewport-fit=cover`, light/dark `theme-color`.

**Tests:** provider applies/removes `data-theme`, persists the choice, defaults to system, survives storage errors.

### Task 2 — Component kit

**Files:** `frontend/src/components/kit/*` (+ tests), `frontend/src/components/ui.tsx` (re-exports for compatibility), `frontend/src/test/setup.ts` (jsdom polyfills Radix needs).

Dependencies: `lucide-react`, `@radix-ui/react-dialog`, `@radix-ui/react-dropdown-menu` (accessible focus trapping, Escape, ARIA — not worth hand-rolling).

- `Button` (primary / secondary / ghost / danger; sm / md; optional icon; loading) — `type="button"` by default.
- `IconButton` (required `label` → `aria-label` + tooltip).
- `Field` (label / hint / error around any control); global input styles cover `Input`/`Select`/`Textarea`/native date pickers (16px on phones so iOS doesn't zoom).
- `SegmentedControl` (view toggles; `aria-pressed`).
- `Modal` (Radix Dialog; centred card on desktop, bottom sheet on phones) and `ConfirmDialog` + `useConfirm()` (promise-based) via `ConfirmProvider`.
- `Menu` (Radix DropdownMenu; items with icon/danger).
- `Card`, `Avatar` (initials + colour, or image), `Chip`, `Badge`.
- `PageHeader` (icon, title, optional view switcher, actions, overflow menu; on phones a search button, and the switcher wraps to its own row).
- `EmptyState` / `Spinner` / `ErrorState` restyled (moved into the kit; `components/ui.tsx` re-exports them).
- Toasts restyled with Lucide icons.

**Tests:** one focused test per component's behaviour (button type default, icon button label, segmented `aria-pressed`, modal open/close/Escape, confirm resolves true/false, menu selection, page header search/menu).

### Task 3 — Responsive shell

**Files:** `frontend/src/shell/*`, `frontend/src/styles/global.css`.

1. `ShellContext` (`openSearch`) so page headers can open the command palette.
2. Desktop (≥ 768px): the left rail keeps icon + label items, gains a brand mark and an **account menu** (avatar → name/email, Settings, Sign out) instead of the "Out" button.
3. Phones (< 768px): no rail; a **bottom tab bar** (Map · Photos · Trips · Docs · More) with safe-area padding. "More" opens a sheet with People, Packing, Settings, Search and Sign out. The documents badge shows on "Docs".
4. Remove the dead "coming soon" path (`ComingSoon`, disabled rail items, `enabled` flags); collapse the five one-line `modules.*.test.ts` files into one table test; replace `AppShell.test.tsx` (which only tested ComingSoon) with real shell tests.
5. Every page uses `PageHeader` (Map, People, Photos, Documents, Planning, Packing, Settings). The Map header drops the invite code (moves to Settings → Family) and the duplicate Sign out; its JSON Export moves into the header's overflow menu until 1.6 removes it.
6. Phone layout fixes: legacy `.modal` becomes a bottom sheet; the trip board scrolls horizontally with snap; packing columns stack; photo filters wrap; the map page stacks map over sidebar above the tab bar.

**Tests:** bottom nav links + badge; More sheet contents; account menu signs out; page header opens search through the context.

### Task 4 — Login and Settings

- Login: brand mark, card on a subtle background, `SegmentedControl` tabs, proper labels, error styling, a password field hint.
- Settings: cards for **Account** (name, email, role), **Family** (name, invite code with copy button), **Appearance** (System / Light / Dark), **Backup** (server owner only). (1.3 adds members, invites and password change.)

**Tests:** settings theme switch changes the preference; invite code is shown and copyable.

### Task 5 — Visual QA

Playwright screenshots of every page at 1440×900 and 390×844, in light and dark. Checks: no horizontal page scroll on phones, header actions inside the viewport, bottom tab bar visible, text contrast sane (spot-check), no console errors, no CSP violations (production build under the nginx CSP).
