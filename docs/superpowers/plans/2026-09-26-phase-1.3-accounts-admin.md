# Phase 1.3 — Accounts, Admin & Onboarding Implementation Plan

**Roadmap:** `docs/superpowers/specs/2026-09-26-completion-roadmap.md` → Milestone 1 → 1.3
**Goal:** Replace open signup and the static family invite code with a proper account model: a setup wizard creates the server admin and first family; the admin invites new families with one-time links; family owners invite members with one-time links; passwords can be changed and reset; sessions can be revoked; and the admin gets a console (families, users, invites, backup/restore, audit log) with the ability to step into any family.

**Decisions this plan relies on (from roadmap §2):** multiple families per server; each login belongs to one family; a separate server-admin role that can see and control everything; new families only by admin invite; phone push (not email) for notifications — so password resets are **links generated by an admin or family owner**, not emails.

---

### Data model (migration `0012_accounts.sql`)

- `users`: `is_admin boolean default false`, `token_version int default 0`, `disabled_at timestamptz`, `last_login_at timestamptz`.
- `families`: `disabled_at timestamptz`. (`invite_code` stays until the 1.4 squash but is no longer used.)
- `invites`: `kind` (`family` = start a new family, `member` = join a family), `token_hash` (SHA-256; the raw token is shown once), `family_id` (member invites), `role` (`owner|member`), `note`, `created_by`, `created_at`, `expires_at`, `used_at`, `used_by`, `revoked_at`.
- `password_resets`: `user_id`, `token_hash`, `created_by`, `created_at`, `expires_at`, `used_at`.
- `audit_log`: `at`, `actor_user_id`, `actor_name`, `action`, `family_id`, `target`, `details jsonb`.
- Upgrade path for existing installs: the owner of the oldest family becomes the server admin (keeps 1.1's "server owner" meaning).

### Auth model

- JWT claims: `{ id, familyId, role, tv, adminView? }`. `tv` = the user's `token_version` at sign-in.
- `requireAuth` verifies the signature **and** loads the user: missing/disabled user → 401; `tv` mismatch → 401 ("signed out everywhere", password changed, role changed, account disabled); family disabled → 403 unless admin. The user's **role and admin flag come from the database**, not the token, so changes apply immediately.
- `adminView`: an admin "stepping into" another family gets a token whose `familyId` is that family and `adminView.homeFamilyId` is their own. Only valid while the user is still an admin. Every switch is audited.
- `requireAdmin`, `requireOwner` preHandlers.

### API

Public:
- `GET /api/auth/config` → `{ firstRun }`.
- `POST /api/auth/setup` (only when no users exist; advisory-locked) → creates family + owner + **admin**, returns a token.
- `POST /api/auth/login` (rate limited; disabled users/families refused; updates `last_login_at`).
- `GET /api/invites/:token` → preview `{ kind, familyName?, role, expiresAt, adminName }` or 404 (unknown/expired/used/revoked).
- `POST /api/invites/:token/accept` `{ displayName, email, password, familyName? }` → family invite: new family + owner; member invite: joins with the invite's role. One use.
- `GET /api/password-resets/:token` → `{ displayName }`; `POST /api/password-resets/:token` `{ password }` → sets it, bumps `token_version`.
- `POST /api/auth/register` is removed (410).

Account (any signed-in user): `GET /api/auth/me` (adds `isAdmin`, `adminView`), `PATCH /api/account` `{ displayName, color }`, `POST /api/account/password` `{ currentPassword, newPassword }` (bumps `token_version`, returns a fresh token), `POST /api/account/sign-out-everywhere`.

Family (owners manage; members read): `GET /api/family` (family, members, pending invites for owners), `PATCH /api/family` `{ name }`, `POST /api/family/invites` `{ role, note?, expiresInDays }` → `{ url, expiresAt }`, `DELETE /api/family/invites/:id`, `PATCH /api/family/members/:id` `{ role }` (never leaves a family without an owner), `DELETE /api/family/members/:id`, `POST /api/family/members/:id/reset-link`.

Admin: `GET /api/admin/overview`, `GET/POST/DELETE /api/admin/family-invites`, `PATCH /api/admin/families/:id` `{ name?, disabled? }`, `DELETE /api/admin/families/:id` (typed-name confirmation; deletes its files too), `GET /api/admin/users`, `PATCH /api/admin/users/:id` `{ isAdmin?, disabled?, role? }` (never removes the last admin), `POST /api/admin/users/:id/reset-link`, `POST /api/admin/view-family` `{ familyId }`, `POST /api/admin/return`, `GET /api/admin/audit`. Backup/restore become **admin-only** (replacing the 1.1 "server owner" stopgap).

Audited: admin view-family/return, family/user changes, invites created/revoked/used, reset links created/used, member removal/role change, backup download, restore.

### Frontend

- Public routes: `/invite/:token` (accept an invite; new-family invites show the privacy notice that the server admin can see all data), `/reset/:token`.
- Login: sign in only (setup on first run); "Forgot your password? Ask your family owner or the server admin for a reset link."
- Settings: **Account** (name, colour, change password, sign out everywhere), **Family** (name; members with role, last seen; owners invite, change roles, remove, make reset links; pending invites with revoke), **Appearance**. Backup moves to Admin.
- **Admin** page (rail + More, admins only): Families (invite a family, rename, disable, delete, view as), Users (make/remove admin, disable, reset link), Backup & restore, Audit log.
- Banner while viewing another family as admin, with "Return to my family".
- Auth fixes: clear the React Query cache on sign-in/out; any 401 signs the user out cleanly (event from the API client).

### Tests

Backend: setup only on an empty server and makes an admin; invite preview/accept (family and member, expired, reused, revoked); login refused for disabled user/family; `token_version` revocation (password change, sign out everywhere, admin disable); role from DB; owner-only family endpoints; last-owner / last-admin guards; admin-only endpoints; view-family token scoping + audit; reset links (owner for own members only, admin for anyone). Frontend: invite page, reset page, settings family section, admin page, admin-view banner, 401 → signed out, cache cleared on sign-out.
